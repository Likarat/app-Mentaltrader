# Validación BDD — 35 historias (HU-001 a HU-035), App Mentaltrader

**Total escenarios**: 117
**Escenarios con violación de formato/estructura**: 16
**Historias con violación de conteo (fuera de 3-5)**: 2 (HU-010, HU-034)

## Nota de formato transversal (no bloqueante)

Las 35 historias usan `- **Dado que**` / `- **Cuando**` / `- **Entonces**` con negrita Markdown y viñeta, en vez de keywords Gherkin en inicio de línea. "Dado que" es alias válido de `Given` en locale `es` — el contenido es correcto, pero para un `.feature` real haría falta un ajuste mecánico de formato.

## 1. Violaciones de conteo (bloqueantes)

- **HU-010**: solo 2 escenarios (mínimo 3), happy + error, sin edge. Agregar un tercer escenario (ej. unicidad con espacios/mayúsculas mixtas).
- **HU-034**: solo 2 escenarios (mínimo 3), happy + edge, sin error. Agregar un tercer escenario (ej. rotación durante un diálogo modal abierto).

## 2. Violaciones de estructura Given/When/Then (16 escenarios)

Patrón dominante: el "Cuando" encadena varias acciones en vez de una sola (ej. "selecciona X y completa Y y presiona Guardar"), cuando el patrón correcto (ya usado bien en HU-001 Esc.1, HU-004 Esc.1) es mover el llenado de campos al "Dado" y dejar el "Cuando" como una sola acción final.

- **HU-001 Esc.3**: Cuando encadena 3 acciones.
- **HU-002 Esc.1, 3, 4**: mismo patrón, Cuando con múltiples acciones.
- **HU-003 Esc.1**: Cuando con 2 acciones. **Esc.3**: Given describe una acción ("escribe"), Cuando mezcla reacción del sistema con acción del usuario.
- **HU-006 Esc.1**: Cuando con 2 acciones + rama condicional (cámara/galería). **Esc.3**: Given describe una acción ("intenta adjuntar").
- **HU-007 Esc.1**: Cuando con sujeto "el sistema" en vez del usuario/disparador. **Esc.2**: Then no observable en caja negra ("sin recalcularla en cada render"). **Esc.3**: Given describe una acción ("selecciona").
- **HU-011 Esc.1**: Given con acción ("selecciona"), Cuando con 2 acciones. **Esc.3**: Given redundante con el Cuando.
- **HU-013 Esc.3**: Given con acción, Cuando describe un resultado del sistema (debería ir en Then).
- **HU-021 Esc.1**: Cuando con 2 acciones distintas encadenadas.
- **HU-024 Esc.1 y HU-030 Esc.1**: Cuando con 2 acciones ("cierra la app y la reabre") — severidad baja, idiom común de test de persistencia, pero viola la regla literal de una sola acción.

Fixes sugeridos detallados por escenario en el reporte completo del agente (disponibles si se necesita el detalle exacto de reformulación por historia).

## 3. Cobertura happy/error/edge — observación sistémica (no bloqueante para la mayoría)

24/35 historias no tienen un escenario de naturaleza "error" explícito (HU-005, HU-008, HU-009, HU-012, HU-014 a HU-019, HU-021 a HU-028, HU-030 a HU-035). En la mayoría es razonable (features de solo lectura/navegación/tema/persistencia sin ruta de error natural). Casos a reconsiderar:

- **HU-015 Esc.3**: etiquetado Edge pero describe un caso normal, no una condición excepcional — cobertura real más pobre de lo que aparenta.
- **HU-016**: sus 3 escenarios son variaciones del mismo caso feliz de performance a distinta escala, sin error ni edge cualitativamente distinto.
- **HU-029**: happy + happy + error, sin edge genuino (ej. rango de un solo día).

## 4. Historias sin problemas de formato

El resto de las 35 (HU-004, HU-005, HU-008, HU-009, HU-012, HU-014 a HU-020 salvo lo señalado, HU-022, HU-023, HU-025 a HU-029, HU-031 a HU-033, HU-035) pasan la revisión de Given=estado / When=una acción / Then=observable.
